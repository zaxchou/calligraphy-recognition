## 一、潘天寿构图：技术选型待讨论项 🔴

### 1.1 开发框架：uni-app Vue3 模式 vs 原生小程序

| 维度 | uni-app (Vue3) | 原生小程序 |
|------|---------------|-----------|
| 学习曲线 | 低（你已有 Vue3 经验） | 中（需学 WXML/WXSS/小程序 API） |
| 代码复用 | 可直接搬运现有关键逻辑（Pinia、computed、watch） | 零复用 |
| echarts-for-weixin | 需要通过 uni-app 插件引入 | 直接使用 |
| 后续扩展 | 可一键打包 H5/App | 仅限微信小程序 |
| 分包 | 天然支持 | 天然支持 |
| 社区 | 大 | 大 |
| 调试 | HBuilderX 或 VS Code + uni-app CLI | 微信开发者工具 |

> **倾向：uni-app Vue3 模式。** 理由：你的前端就是 Vue3，Pinia store 的思路可以直接复用。唯一代价是多一层 uni-app 的适配学习，但比从零学 WXML 小得多。

> **讨论：你倾向 uni-app 还是原生小程序？之前用过吗？**

### 1.2 echarts-for-weixin：雷达图能否直接用？

当前网页端用 `echarts.init()` 渲染 7 维雷达图（数据来自 `report.dimensions` 和 `report.checks`）。

echarts-for-weixin 是 ECharts 官方维护的小程序组件，原理是用 Canvas 2D 渲染。雷达图是其内置图表类型，理论上直接支持。

**但是需要验证的点：**
- uni-app 中引入 echarts-for-weixin 的姿势（npm 包 vs 手动复制）
- 分包场景下，ECharts 本体放主包还是分包？（建议分包预加载）
- 雷达图的 `axisLabel` / `tooltip` 在小程序中渲染是否正常

> **建议：** Phase 0 的第一个验证任务就是搭一个 demo 页面跑通 echarts-for-weixin 的雷达图。如果不行，降级方案是**后端渲染雷达图 PNG**。

> **讨论：你是倾向先用 echarts-for-weixin 试试，还是直接后端出雷达图 PNG 省事？**

### 1.3 Markdown 渲染组件选型

当前网页端有自研的 `renderMarkdown()` 函数（约 173 行，支持标题、列表、表格、粗体、图片、代码块等）。

小程序端需要替代方案。两个主流选项：

| 方案 | 体积 | 功能 | 维护状态 |
|------|------|------|----------|
| **mp-html** | ~100KB | 富文本渲染，支持 Markdown 插件 | ✅ 活跃 |
| **towxml** | ~300KB | 专门 Markdown → WXML，支持 LaTeX/流程图 | ⚠️ 更新较慢 |

> **倾向：mp-html。** 轻量、够用，LLM 输出的 Markdown 主要是标题+列表+表格+粗体，不需要 LaTeX。

> **讨论：你有偏好吗？还是我先用 mp-html 试试？**

### 1.4 轮询的细节参数

当前 SSE 降级轮询是 1 秒间隔。小程序端需要考虑：

| 参数 | 建议值 | 理由 |
|------|--------|------|
| 轮询间隔 | **1.5 - 2 秒** | 小程序网络可能比网页慢，稍微放宽 |
| 超时上限 | **5 分钟** | 当前构图分析通常 30-90 秒完成，5分钟是安全上限 |
| 失败重试 | **3 次**，间隔递增 | 应对弱网 |
| 后台轮询 | **暂停** | 小程序切后台后停止轮询，回到前台恢复 |

当前后端 `GET /task/{id}` 返回字段：[需要核实]。理想情况下需要返回：
- `status`（pending/processing/done/failed）
- `progress`（0-100）
- `stage_text`（当前阶段描述，如"正在分析虚实留白..."）
- `eta_seconds`（预计剩余秒数）
- `error_message`（如果失败）

> **待核实：** 当前轮询接口是否返回上述所有字段？还是只有部分？需要我去查一下后端代码吗？

### 1.5 SVG 起承转合覆层：后端需改什么？

当前逻辑：
1. 如果 `report.assets.arrow_overlay_url` 存在 → 直接显示 PNG
2. 否则 → 用 `SvgOverlay` 组件在前端叠加 SVG

小程序方案：**只用方式 1**，后端**始终生成** `arrow_overlay_url`。

需要确认的点：
- 当前什么情况下后端不生成 `arrow_overlay_url`？是配置开关还是算法没跑通？
- 是否只是一行默认值的问题，还是需要调构图管线的执行顺序？

> **讨论：需要我去看后端构图模块的 arrow_overlay 生成逻辑吗？**

### 1.6 选图后的体验：预览 + 裁剪？

当前网页端选了图之后：本地预览（URL.createObjectURL）→ 点"开始分析"。

小程序端考虑两个增强：

| 功能 | 是否需要 | 理由 |
|------|---------|------|
| **图片预览** | ✅ 必须 | 让用户确认选了正确的图 |
| **图片裁剪** | ⚠️ 可选 | 用户可能拍了大画的一部分，裁剪后分析更准 |
| **压缩** | 🤔 待定 | wx.uploadFile 自带压缩？还是需要前端先压？ |

> **讨论：裁剪功能是加分项，不做也可以——先做最简单的选择→预览→上传？还是你觉得选图后加个裁剪步骤更好？**

### 1.7 结果页的展示元素清单

基于"后端出图 + 小程序展示"策略，结果页需要展示：

| 元素 | 数据来源 | 展示方式 |
|------|---------|---------|
| **总评分** | `report.summary.total_score` | 大字 + 圆形进度环（CSS 动画） |
| **LLM 分析文本** | `report.llm.text` | mp-html 富文本渲染 |
| **原图** | `report.assets.thumb_url` | `<image>` 可点击放大 |
| **起承转合覆层图** | `report.assets.arrow_overlay_url` | `<image>` 可点击放大 |
| **七维雷达图** | `report.dimensions` + `report.checks` | echarts-for-weixin Canvas |
| **分享/保存** | — | wx 分享 API |

**不需要的（留网页端）：**
- ❌ 下载 PDF 报告（小程序不支持）
- ❌ 历史记录列表（后续可加"我的分析"但不急）

### 1.8 页面状态机设计

潘天寿构图这一个页面有 3 个明确状态：

```
┌──────────┐   选择图片    ┌──────────┐   点开始分析   ┌──────────┐
│  IDLE    │ ──────────→ │ PREVIEW  │ ────────────→ │ UPLOADING│
│ 空状态    │              │ 图片预览  │                │ 上传中    │
└──────────┘              └──────────┘                └────┬─────┘
                                                           │ 上传成功
                                                           ▼
┌──────────┐   轮询完成    ┌──────────┐   出错          ┌──────────┐
│  RESULT  │ ←────────── │ POLLING  │ ←───────────── │  ERROR   │
│ 结果展示  │              │ 进度轮询  │                  │ 出错提示  │
└──────────┘              └──────────┘                  └──────────┘
```

这个状态机在小程序中用 `ref('idle')` 管理即可，非常干净。
