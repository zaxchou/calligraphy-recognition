## 二、模块 A：李鱓题跋展示（纯展示小程序）

### 2.1 现状分析

当前题跋分析的入口页面是 `TubiAnalysis.vue`（2644行），它本身是一个"协调器"——模板仅 ~100 行，通过 `v-if` 在 `TubiHome`（作品列表）和 `TubiDetail`（单幅详情）之间切换。所有编辑/删除/上传/触发AI分析等管理操作都写在这个文件里。

### 2.2 小程序需要哪些页面？

#### 确定需要的（纯展示）：

| 页面 | 对应现组件 | 功能 | 复杂度 |
|------|-----------|------|--------|
| **作品列表页** | TubiHome | 画廊列表 + 艺术家筛选 + 标签筛选 + 分页 + 搜索 | 🟡 中 |
| **作品详情页** | TubiDetail | 单幅作品 → Canvas 区域标注图 + 面积饼图 + 趋势图 + 朋友圈图 + 题跋内容 + 作品信息表 | 🔴 高 |

#### 可以考虑的：

| 页面 | 功能 | 建议 |
|------|------|------|
| **排行榜** (TubiRanking) | 数据统计排行 | 🟢 值得做，纯表格/图表，差异化体验 |
| **作品搜索** | 关键词搜索 + 结果预览 | 🟡 可做，但要砍掉删除/编辑等管理操作 |

#### 明确不要的（保留网页端）：

- ❌ TubiEditDialog — 编辑作品信息
- ❌ 删除作品
- ❌ 替换图片/上传图片
- ❌ 触发 AI 分析 (autoAnalyze)
- ❌ 清空全部
- ❌ 跳转手动标注 (InscriptionAnnotator)
- ❌ 复制链接 / window.open 新窗口
- ❌ 管理后台 (ContentVerify)
- ❌ 尺寸录入 (DimensionInput)

### 2.3 核心难点拆解

#### 难点 1：TubiDetail 的 Canvas 区域标注图

当前用 `<canvas>` 绘制原图叠加题跋/绘画/留白区域的颜色标注（约 118 行代码，[L728-L845](https://github.com/user-attachments/assets/TubiAnalysis.vue#L728-L845)）。

- **问题**：小程序 Canvas 2D API 与 Web Canvas 差异大，API 签名不同
- **方案 A**：后端生成覆层图 PNG，前端直接显示 `<image>`（最简单）
- **方案 B**：小程序 Canvas 2D 重新实现（更灵活但工作量大）
- **建议**：方案 A，反正是展示，后端渲染一张图出来就行

#### 难点 2：ECharts 图表（3 个）

当前有：趋势图、朋友圈关系图、饼图。都用 `echarts.init()` 初始化。

- **方案**：`echarts-for-weixin`（社区维护的小程序版 ECharts）
- **风险**：朋友圈图是较复杂的 layout，需验证兼容性
- **替代**：如果某些图表不兼容，可以后端渲染成图片返回

#### 难点 3：趋势图的数据交互

当前趋势图是动态筛选的——选择不同艺术家、不同数据范围，图表实时变化。

- 小程序中可以保持相同交互，筛选条件 → API 重新请求 → 图表更新

#### 难点 4：册页导航（上一幅/下一幅）

当前有册页内作品切换导航（`loadAlbumNavigation` / `navigateToAlbumItem`）。

- 可以保留，纯 API 调用，无特殊技术障碍

#### 难点 5：搜索弹窗中的删除按钮

当前搜索结果弹窗（TubiSearchDialog）中有编辑和删除操作。

- **方案**：搜索功能可以保留，但搜索结果中砍掉删除/编辑按钮

### 2.4 小程序页面规划

```
pages/
├── tubi/
│   ├── list/          ← 作品列表（TubiHome 对应）
│   │   功能：画廊展示、艺术家筛选、标签筛选、分页、搜索入口
│   └── detail/        ← 作品详情（TubiDetail 对应）
│       功能：Canvas覆层图、面积饼图、趋势图、朋友圈图、题跋内容、作品信息
├── ranking/           ← 排行榜（可选）
└── search/            ← 搜索页（可选）
```

### 2.5 需调用的 API（全部已存在，无需后端改动）

| API | 用途 | 当前调用方 |
|-----|------|-----------|
| `GET /api/v1/tubi/results?skip=&limit=&artist=&tag=` | 作品列表 + 筛选 + 分页 | TubiHome |
| `GET /api/v1/tubi/result/{id}` | 单幅作品详情 | TubiDetail |
| `GET /api/v1/tubi/search?keyword=` | 关键词搜索 | TubiSearchDialog |
| `GET /api/v1/tubi/ranking?tag=` | 排行榜数据 | TubiRanking |
| `GET /api/v1/tubi/album/{id}/navigation` | 册页导航 | 册页导航 |

**结论：后端零改动。** 所有 API 已存在且功能完备，小程序直接调用 `wx.request` 即可。

## 三、模块 B：潘天寿构图上手（上传 + 等待 + 结果）

### 3.1 现状分析

`CompositionAnalyze.vue`（2087行），核心流程：

```
用户选择图片 → 本地预览 → 点"开始分析"
  → POST /upload (传文件, 120s timeout)
  → SSE /task/{id}/events (实时进度)
  → status=done → GET /report/{id}
  → 结果页: Markdown分析文 | 评分 | 原图 | SVG叠加 | 雷达图
```

### 3.2 小程序需要的页面

| 页面 | 功能 | 复杂度 |
|------|------|--------|
| **构图分析**（主页面） | 上传图片 → 进度展示 → 结果呈现 | 🔴 高 |

就是**一个页面**搞定全过程。没有管理后台、没有历史记录（可以简化为可选的"我的分析"列表）。

#### 可选扩展：

| 页面 | 建议 |
|------|------|
| 分析历史列表 | 低优先级，简单列表页 |
| 构图报告打印 (CompositionPrint) | 暂不需要，小程序内查看即可 |

### 3.3 核心难点拆解

#### 难点 1：文件上传

- **当前**：`el-upload` + `URL.createObjectURL()` 预览
- **小程序**：`wx.chooseImage({ sourceType: ['album', 'camera'] })` → 获取 `tempFilePath`
- **上传**：`wx.uploadFile({ url: '/api/v1/composition/upload', filePath })`
- **预览**：直接用 `tempFilePath` 渲染 `<image>`
- **注意事项**：`wx.uploadFile` 的超时和 FormData 构造方式与 Axios 不同，需要封装

#### 难点 2：SSE 实时进度 → 需要替代

- **当前**：`EventSource` 连接 SSE 端点 `/api/v1/composition/task/{id}/events`，推送 JSON 进度数据
- **小程序不支持 EventSource** ❌
- **方案 A**：后端新增 WebSocket 端点（`ws://...`），小程序用 `wx.connectSocket` 监听
- **方案 B**：纯轮询（前端每秒轮询 `GET /task/{id}`，降到 SSE 出错）
- **方案 C**：**后端 SSE → 前端轮询**（当前已有降级机制，直接用！）

> ⭐ **推荐方案 C**：当前代码已经有 SSE 失败降级到轮询的逻辑（[L861-L871]），就照着这个思路——小程序直接用轮询。1秒间隔轮询 `GET /task/{id}` 更新进度。对体验影响很小，且后端完全不用改。

#### 难点 3：ECharts 雷达图

- **方案**：`echarts-for-weixin`

#### 难点 4：SVG 起承转合覆层 (SvgOverlay)

当前有两种渲染方式：
1. 如果后端生成了 `arrow_overlay_url`（覆层 PNG），直接显示图片
2. 否则用 `SvgOverlay` 组件在原图上叠加 SVG 矢量标注（箭头、定位点等）

- **方案 A**：后端**总是生成覆层 PNG**，小程序直接用 `<image>` 显示（最简单）
- **方案 B**：小程序 Canvas 2D 重新绘制 SVG 标注
- **建议**：方案 A。后端构图模块已经有生成 `arrow_overlay_url` 的能力，只需确保总是生成即可（可能需要改一行默认行为），小程序端零额外工作。

#### 难点 5：Markdown 渲染

当前结果中的 LLM 分析文本是 Markdown 格式，通过 `renderMarkdown()` 自研渲染器转 HTML。

- **方案**：小程序端的 markdown 渲染组件（如 `mp-html` / `towxml`）
- **注意**：自研渲染器支持的自定义格式需要移植或简化

#### 难点 6：下载 PDF 按钮

当前有"下载 PDF 报告"按钮 → 打开 `/composition/print/:taskId`。

- **小程序**：无法直接下载 PDF。可改为"复制链接"或"在浏览器中打开"。
- **替代**：后端生成 PDF URL，用户可复制或分享。

### 3.4 小程序页面规划

```
pages/
└── composition/
    └── analyze/       ← 主页面（上传 + 进度 + 结果全部在这里）
         ├── 阶段1: 选择图片 (wx.chooseImage)
         ├── 阶段2: 上传中 + 分析进度 (轮询)
         └── 阶段3: 结果展示 (Markdown + 评分 + 雷达图 + SVG覆层)
```

### 3.5 需调用的 API

| API | 用途 | 现状 |
|-----|------|------|
| `POST /api/v1/composition/upload` | 上传图片 | ✅ 已存在，`wx.uploadFile` 适配 |
| `GET /api/v1/composition/task/{id}` | 轮询进度 | ✅ 已存在（原降级通道） |
| `GET /api/v1/composition/report/{id}` | 获取完整报告 | ✅ 已存在 |

**需要后端改动：**

| 改动项 | 原因 | 工作量 |
|--------|------|--------|
| 轮询 `GET /task/{id}` 返回更多字段？ | 确保轮询返回的数据足够替代 SSE 的阶段信息 | 微小：核实即可 |
| 确保 `arrow_overlay_url` 始终生成 | 小程序端不实现 SvgOverlay 组件 | 微小：改一行默认行为 |

**结论：后端几乎零改动。** 最多两处微小调整。

## 四、架构决策：一个 vs 两个小程序

| 维度 | 一个小程序（双Tab） | 两个独立小程序 |
|------|-------------------|---------------|
| **用户体验** | 一站式，切换方便 | 各自独立，入口分散 |
| **开发成本** | 共享 uni-app 工程、共享 API 封装 | 两套工程，部分代码重复 |
| **包体积** | 两个模块加一起可能较大（ECharts × 2） | 各自独立较小 |
| **审核** | 一次审核 | 两次审核 |
| **品牌** | 统一品牌 | 可各自品牌 |
| **维护** | 一份代码库 | 两份代码库 |
| **迭代** | 耦合度高 | 各自独立迭代 |
| **分包可行？** | ✅ uni-app 支持分包，两模块可各自为独立分包，主包很小 | — |

> ⭐ **倾向推荐：一个 uni-app 工程，用分包隔离两个模块。**
>
> - 主包（<500KB）：首页入口 + 共享工具/API封装
> - 分包A（李鱓题跋）：作品列表 + 详情 + 排行
> - 分包B（潘天寿构图）：上传 + 进度 + 结果
>
> 如果未来只打算做其中一个，或者两个模块的受众完全不同，再考虑拆成两个。

## 六、开发顺序建议（不论合/分）

```
Phase 0：基础设施搭建（1周，1人）
  ├── uni-app 项目初始化（Vue3 模式）
  ├── 分包配置（主包 + 两个模块分包）
  ├── API 封装层（wx.request + 拦截器 + 错误处理）
  ├── echarts-for-weixin 集成 + 验证
  └── Markdown 渲染方案选型 + 集成

Phase 1：潘天寿构图（2-3周，1人）⏩ 先做
  ├── 1 个页面：上传 → 轮询进度 → 结果展示
  ├── echarts-for-weixin 雷达图
  ├── 覆层图片显示
  └── 简单易验证，快速端到端跑通

Phase 2：李鱓题跋展示（3-4周，1-2人）
  ├── 作品列表页：画廊 + 筛选 + 分页 + 搜索
  ├── 作品详情页：Canvas掩码图 + 饼图 + 趋势图 + 朋友圈图
  ├── 排行榜（可选）
  └── 内容丰富，等 Phase 1 验证技术栈后再做

Phase 3：完善 + 审核（2-3周）
  ├── 微信登录（如需）
  ├── UI 打磨
  ├── 性能优化（图片懒加载、分包预加载）
  └── 提交审核
```
