## 用户需求

一次性修复题跋分析系统的4个问题：

1. **图片不显示**：上传的11张新图在 gallery 里看不到。根因是数据库 `thumbnail_path` 字段存了错误的前缀 `static/thumbnails/`，应为 `data/thumbnails/`，导致前端 getResults API 检查文件存在时路径不匹配，返回空 URL。

2. **内容分析统计空白**：36条已校对记录校对完后，主题分布和情感分析全是空白。根因是 `POST /api/v1/content-analysis/batch` 默认 `force_reanalyze=False`，会跳过 `inscription_verified=1` 的已验证记录，这些记录从未进入分析流程。

3. **校对列表排序错误**：打开校对页面时，已校对的36条排在前，未校对的11条排在后，不方便工作。根因是 `GET /api/v1/content-analysis/records` 的 SQL `ORDER BY year, id`，已校对记录因 `inscription_content IS NOT NULL` 条件被包含且排在前面。

4. **面积统计全部错误**：新分析的11张图片 painting_percent=0%、blank_percent=0%。根因是 `batch_process_tubi.py` 在检测到 `inscription_mask` 时，用 OpenCV 像素计数结果直接覆盖 `painting_percent=0.0`、`blank_percent=0.0`，把 `calculate_area_stats_with_overlap_correction` 算出的正确值覆盖掉了。

## 核心功能

- 修复数据库路径前缀，让缩略图 URL 正确返回
- 让已校对记录能重新进入内容分析流程
- 改变校对列表排序，优先显示未校对记录
- 修复面积计算覆盖逻辑，保留正确的 painting/blank 统计值

## 技术方案

### Bug 1：修复 thumbnail_path 前缀（SQL UPDATE）

直接 UPDATE 数据库，把 `static/thumbnails/` 前缀改成 `data/thumbnails/`，涉及 id >= 57 的11条新记录。

### Bug 2：触发已校对记录的内容分析（API 调用）

执行 `POST /api/v1/content-analysis/batch?force_reanalyze=true`，对全部49条记录重新计算 `content_analysis`（包含 themes/sentiment/char_count 等），更新 `theme_tags` 字段。

### Bug 3：修改校对列表 SQL 排序（content_analysis.py + TubiAnalysis.vue）

- 后端：`get_records` 的 ORDER BY 改为优先排未校对记录 `(inscription_verified = 0 OR inscription_verified IS NULL) DESC, id DESC`
- 前端：`loadHistory` 调用时带上 `sort=unverified_first` 参数（现有代码已支持）

### Bug 4：修复面积覆盖逻辑（batch_process_tubi.py + tubi_worker.py）

删除覆盖逻辑，改为在 `area_stats` 基础上增量修正 `inscription_percent`：

- 旧逻辑：`painting=0, blank=0` 直接覆盖
- 新逻辑：保留 `calculate_area_stats_with_overlap_correction` 的三值结果（inscription/painting/blank），如果 `inscription_mask` 存在则用像素级精确值替换 inscription_percent，保留 painting 和 blank 不变
- 同时在 tubi_worker.py 应用同样修复

### 重新入队 pending 任务

id=67（长年百子富贵图）状态为 pending，需要重新入队让 worker 处理。
