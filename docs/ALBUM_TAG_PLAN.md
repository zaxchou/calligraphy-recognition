# 册页与标签功能完整实现文档

## 一、产品定位

### 1.1 功能愿景
为李鱓等画家的册页作品集提供系统化管理，同时建立灵活的标签体系，实现作品的精细化分类检索。

### 1.2 核心差异

| 维度 | 册页 | 标签 |
|------|------|------|
| 归属关系 | 一幅作品只能属于一个册页 | 一幅作品可属于多个标签 |
| 顺序 | 有固定顺序（album_index） | 无固定顺序（或用权重） |
| 尺寸同步 | 支持批量同步尺寸 | 不支持 |
| 典型场景 | 《花鸟册页十开》10 幅 | "写意"、"工笔"、"有题跋"、"精品" |

---

## 二、数据模型设计

### 2.1 现有字段（已存在）
```sql
-- 册页分组
album_name = Column(String(200), nullable=True)   -- 册页名称，如"花鸟册"
album_index = Column(Integer, nullable=True)     -- 册页页码，如 1 表示第一开
```

### 2.2 新增字段（标签系统）
```sql
-- 标签关联（JSON 数组，简化设计避免多对多表）
tags = Column(String(500), nullable=True)  -- 存储标签名数组，如"写意,工笔,有题跋"
```

### 2.3 统一分组管理理念
册页和标签本质都是"分组"，只是在 UI 和部分行为上有差异。共用架构如下：

```
分组类型 = "album" | "tag"
分组元数据 = { name, created_at, ... }
分组成员关系 = { record_id, group_name, group_type, index/weight }
```

## 三、后端 API 设计

### 3.1 册页 API

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/tubi/albums` | 获取所有册页列表（含统计） |
| POST | `/tubi/albums` | 创建新册页 |
| GET | `/tubi/albums/{album_name}` | 获取册页详情（含作品列表，按 album_index 排序） |
| PUT | `/tubi/albums/{album_name}` | 更新册页信息（如重命名） |
| DELETE | `/tubi/albums/{album_name}` | 删除册页（作品 album_name/album_index 置 NULL，不删除记录） |
| POST | `/tubi/albums/{album_name}/items` | 添加作品到册页（支持批量，自动分配 album_index） |
| DELETE | `/tubi/albums/{album_name}/items/{record_id}` | 从册页移除作品（清除该作品的 album_name/album_index） |
| PUT | `/tubi/albums/{album_name}/reorder` | 重新排序册页内作品（body: {order: [id1, id2, ...]}） |
| GET | `/tubi/albums/navigation/{record_id}` | 获取指定作品的册页导航信息（同册页其他作品列表） |

### 3.2 标签 API

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/tubi/tags` | 获取所有标签列表（含使用统计） |
| POST | `/tubi/tags` | 创建新标签 |
| PUT | `/tubi/tags/{tag_name}` | 重命名标签 |
| DELETE | `/tubi/tags/{tag_name}` | 删除标签（从所有作品中移除该标签） |
| GET | `/tubi/tags/{tag_name}/items` | 获取使用某标签的所有作品 |
| PUT | `/tubi/tags/{tag_name}/items` | 更新作品标签（body: {record_ids: [], action: "add"/"remove"}） |

### 3.3 统计 API 扩展

在现有统计接口中新增：
```json
{
  "album_stats": {
    "total_albums": 5,
    "total_album_items": 42,
    "albums_by_artist": {...}
  },
  "tag_stats": {
    "total_tags": 15,
    "top_tags": [{"name": "写意", "count": 30}, ...]
  }
}
```

### 3.4 删除行为规范

**删除册页时：**
```sql
UPDATE tubi_analyses
SET album_name = NULL, album_index = NULL
WHERE album_name = :album_name
-- 不删除任何记录，只是解除关联
```

**删除标签时：**
```sql
-- 从 tags 字段中移除该标签名
UPDATE tubi_analyses
SET tags = REPLACE(tags, '标签名,', '')
WHERE tags LIKE '%标签名%'
```

## 八、风险与注意事项

1. **数据库兼容性**：使用 JSON 数组存储标签，SQLite 原生支持，无需创建多对多关联表
2. **并发安全**：批量操作使用事务保证一致性
3. **性能考虑**：册页和标签查询利用现有索引
4. **数据迁移**：现有 album_name/album_index 数据保持不变
